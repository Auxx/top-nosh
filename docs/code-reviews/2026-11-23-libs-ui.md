# Code Review: `libs/ui`

- **Date:** 2026-11-23
- **Scope:** everything under `libs/ui` (14 components/dialogs, 5 pipes, 1
  directive, theming, tests, stories, project config). How `apps/web` uses the
  library was checked where it affects a finding.
- **Focus:** code quality, Angular best practices (Angular 22, signals,
  zoneless), usability on desktop and mobile (responsiveness, touch,
  accessibility, i18n).
- **Baseline:** `nx run ui:lint` passes; `nx run ui:test` passes (18 suites, 41
  tests); `tsc -p libs/ui/tsconfig.lib.json --noEmit` **fails** (see H2).

## Summary

The library is in good shape on modern Angular basics. Every component is
standalone and `OnPush`. It uses signal `input()`/`output()`/`computed()`, the
new control flow (`@if`, `@for`, `@let`), `host` metadata instead of
`@HostBinding`, and `inject()`. Tests run zoneless with
`errorOnUnknownElements`/`errorOnUnknownProperties`.

The main problems are:

1. Two visible bugs: stray text rendered by `ui-block-notice`, and form errors
   that don't show in common cases with `uiWhenError`.
2. Scaffolding was never finished: Storybook stories without Storybook, a broken
   type-check, placeholder tests, an orphaned template, and a generator README.
3. The library isn't self-contained. It depends on design tokens, translation
   keys and routes that are defined in `apps/web`.
4. Mobile and accessibility gaps: icon-only buttons with no accessible name, the
   grid can overflow, touch targets are small, hover-only styles, and hard-coded
   English strings even though the app ships a Russian locale.

## High

### H1. `ui-block-notice` renders the literal text `libs/ui/src/index.ts`

`libs/ui/src/content/components/block-notice/block-notice.component.html:4`

The template's last line is the stray string `libs/ui/src/index.ts`, probably
from an editor paste. Every notice block in the app shows this path under its
projected content. The smoke test doesn't check the DOM, so it didn't catch it.

**Fix:** delete line 4. Add a test that checks the host's `textContent` contains
only the projected content.

### H2. The library doesn't compile under its own `tsconfig.lib.json`

`libs/ui/tsconfig.lib.json:10-20`, `libs/ui/src/**/*.stories.ts`

`tsconfig.lib.json` includes `src/**/*.ts` and doesn't exclude `*.stories.ts`.
Storybook isn't installed in the workspace: there's no `@storybook/*` package
and no `.storybook` config. `confirmation.dialog.stories.ts` also calls
`jest.fn()`, and `jest` isn't available in the lib's `types: []`. Result: 30+ TS
errors (`TS2307 Cannot find module '@storybook/angular'`, `TS2304 Cannot find
name 'jest'`). This doesn't show up today only because `apps/web` compiles the
sources through its path mapping and never touches the stories. Any future
`build`/`typecheck` target or IDE project check fails.

**Fix:** either set Storybook up properly (`nx g @nx/storybook:configuration
ui`) and replace `jest.fn()` with a plain `{ close: () => {} }`, or delete the
stories. In both cases, add `"src/**/*.stories.ts"` to the `exclude` list in
`tsconfig.lib.json`.

### H3. `uiWhenError` doesn't show errors when a field is touched without changing its value

`libs/ui/src/control/directives/when-error/when-error.directive.ts:46-62`

The directive only re-checks on `control.statusChanges`. That observable does
**not** emit on `markAsTouched()`/blur, and doesn't emit on `markAllAsTouched()`
either. The directive also never checks the state when it's first created.
Consequences:

- A user focuses a required field and tabs away. `mat-form-field` turns red
  (touched + invalid), but no `<mat-error>` text appears. The field is
  highlighted with no explanation.
- If a submit handler calls `form.markAllAsTouched()`, fields the user never
  touched get no messages. No submit handler in the app does this yet, but it's
  the standard Angular pattern.
- If the directive is created while the control is already invalid and touched
  (for example inside an `@if`), nothing appears until the next value change.

The directive is used in 9 forms (login, onboarding, password change, recipe
form, user create/edit, …), so this affects most data entry.

**Fix:** subscribe to `control.events` (unified control events, Angular 18+). It
covers `TouchedChangeEvent`, `StatusChangeEvent` and the rest. Use
`startWith(null)` so the directive evaluates once immediately. Simplify the
subscription management with the effect's `onCleanup`:

```ts
effect(onCleanup => {
  const control = this.uiWhenError();
  const code = this.uiWhenErrorErrorCode();
  const sub = control.events.pipe(startWith(null)).subscribe(() => this.render(control, code));
  onCleanup(() => sub.unsubscribe());
});
```

`takeUntilDestroyed`, `controlSub` and the injected `DestroyRef` can then go.
The spec file (`when-error.directive.spec.ts`) is a placeholder
(`expect(true).toBeTruthy()`) and needs real tests for
touched/dirty/submit/multiple error codes.

### H4. Icon-only buttons in the menu bar have no accessible name

`libs/ui/src/navigation/components/menu-bar/menu-bar.component.html:15-19,
23-27`

The logout button and the mobile "more" (`more_vert`) button contain only a
`<mat-icon>`. `MatIcon` is `aria-hidden` by default, so screen readers announce
them as "button" with no label. The "more" button is the **only** way to
navigate on a portrait phone.

**Fix:** add `[attr.aria-label]="t(item.label)"` to the icon button and
`[attr.aria-label]="t('menu')"` to the trigger. Add `matTooltip` for mouse
users.

## Medium

### M1. The menu bar hard-codes app routes, brand and labels

`libs/ui/src/navigation/components/menu-bar/menu-bar.component.ts:15-21`,
`.html:3`

A UI library component knows `/dashboard`, `/recipes`, `/logout`, … and the
product name. It isn't reusable, and every navigation change requires editing
the library. The brand `"Top Nosh"` is hard-coded even though the translation
key `ui.MenuBar.title` already exists.

**Fix:** accept `items = input.required<MenuItem[]>()` (export the `MenuItem`
interface) and either a `title` input or `{{ t('title') }}`. Use `static`/module
constants instead of a factory function called per instance.

### M2. Menu bar navigation semantics and mobile state

`menu-bar.component.html:15-17, 30-34`

- `<button [routerLink]>` is used for navigation (logout icon and all
  `mat-menu-item`s). Links should be `<a>`. That keeps middle-click / long-press
  "open in new tab", the status-bar URL preview, and correct screen-reader
  semantics. `mat-menu-item` and `matIconButton` both support `<a>`.
- The mobile menu has no `routerLinkActive` indication. On a phone the user
  can't tell which section they're in.
- `<mat-icon size="18">` has no effect: `size` isn't a `MatIcon` input and
  nothing styles it. Remove it.
- The `<mat-toolbar>` has no surrounding `<nav>` landmark / `aria-label`.

### M3. Menu bar styling depends on Material internals and has questionable contrast

`menu-bar.component.scss:13-60`

- Selectors like `a.action.mat-mdc-button-base.mat-unthemed` depend on private
  MDC class names that Material has renamed before. Apply
  `button-overrides`/`icon-button-overrides` to a class of your own (or to
  `:host`), which is what those override mixins are designed for.
- The toolbar text uses `--mat-sys-primary-container` on a `--mat-sys-primary`
  background, and inactive links use `--mat-sys-inverse-primary`. These aren't
  Material's guaranteed-contrast pairs (`on-primary` is). With the 12
  user-selectable palettes in `theming.scss`, some combinations, especially in
  dark mode where `primary` is light, are likely to fall below WCAG AA 4.5:1.
  Verify each palette in light and dark, or switch to `on-primary`.
- `position: fixed; z-index: 1000` on mobile ties with the CDK overlay container
  (`z-index: 1000`). Overlays only win because of DOM order. Use a lower value
  (for example `100`).
- The fixed toolbar doesn't account for `env(safe-area-inset-top)` on notched
  devices if the app ever uses `viewport-fit=cover` or runs as a PWA.

### M4. `ui-card-grid` can overflow horizontally

`libs/ui/src/layouts/components/card-grid/card-grid.component.scss:3, 9`

`minmax(max-content, 400px)`: when a card's max-content width is larger than
400px (a long unbreakable recipe name, a URL, a wide image), CSS ignores the
max, and the column becomes as wide as the content. On a 360px phone this causes
horizontal page scroll. Landscape phones and small tablets (600–840px) get two
`max-content` columns and overflow even sooner.

**Fix:** `grid-template-columns: repeat(auto-fit, minmax(min(100%, 280px),
400px));`. This also removes the need for the media query and handles landscape
correctly.

### M5. Inconsistent breakpoints across components

`card-grid.scss:8`, `menu-bar.scss:8,22,40,50,65` use `(max-width: 599.98px) and
(orientation: portrait)`. `page-header.scss:13` uses `(max-width: 599.98px)`
only.

On a landscape phone (for example 640×360), the menu bar shows the full desktop
link row. The page header doesn't switch at all, because the width is over
600px. The `599.98px` value is repeated 7 times.

**Fix:** define the breakpoints once, as a SCSS mixin in
`libs/ui/src/styles/_breakpoints.scss`, aligned with CDK `Breakpoints.Handset`.
Base layout decisions on width (and `hover`/`pointer` media features), not on
orientation.

### M6. The library depends on design tokens defined in the app

All component SCSS files use `--dim-*` and `--page-max-width`, but these are
declared in `apps/web/src/styles.scss:10-27`. `theming.scss` lives in the
library but is pulled in through a relative path (`@use
"../../../libs/ui/src/styles/theming"`).

The library can't render correctly anywhere else, including Storybook and tests.
Components silently get `gap: 0` / `padding: 0` if the tokens are missing.

**Fix:** move the token definitions into `libs/ui/src/styles/_tokens.scss`
(exported together with theming). Reference it through
`stylePreprocessorOptions.includePaths` (for example `@use 'ui/theming'`)
instead of a relative path.

### M7. Hard-coded English strings; the app ships `ru` too

- `confirmation.dialog.html:6-7`: defaults `'No'` / `'Yes'`.
- `markdown-preview.dialog.html:1, 6, 10`: `'Description Preview'`, `'No
  Markdown content was provided.'`, `'Close'`.
- `unit.pipe.ts:11-18`: `g`, `item(s)`, `teaspoon(s)`, `table spoon(s)` (also
  misspelled: should be **tablespoon**), with English-only plural rules. Russian
  has three plural forms.
- `scale-quantity.pipe.ts:12`: `toString()` always uses `.` as the decimal
  separator. Russian expects `0,5`.

Other library components already use Transloco (`ui.PageHeader`, `ui.MenuBar`,
…), so these are inconsistent as well.

**Fix:** route the strings through `TranslocoDirective`/`translateSignal`. Use
`@jsverse/transloco-messageformat` (already a dependency) for unit plurals.
Format numbers with `Intl.NumberFormat(activeLang)`, or `TranslocoDecimalPipe`
if you add `@jsverse/transloco-locale`. Because the unit pipe would then depend
on the active language, it has to be `pure: false` or take the language as an
argument. A signal-based helper is the cleaner option.

### M8. `DomainPipe` can throw on still-supported Safari/iOS versions

`libs/ui/src/content/pipes/domain/domain.pipe.ts:6`

`URL.parse()` exists only since Safari/iOS 18.0 and Chrome 126. The workspace
has no `.browserslistrc`, so Angular's default "widely available" target
applies, which still includes iOS 17. On iOS 17, `URL.parse` is `undefined`, so
the pipe throws `TypeError` and breaks the template that uses it.

The pipe is also misnamed: it returns the **origin** (`https://example.com`),
not the domain (`example.com`). It has no tests.

**Fix:**

```ts
transform(value: string): string {
  try { return new URL(value).hostname; } catch { return value; }
}
```

Add a spec. Rename it, or switch to `hostname`, to match the intent.

### M9. `ui-info-card` interactive mode: the consumer has to supply behavior, and hover is used on touch

`libs/ui/src/layouts/components/info-card/info-card.component.scss:17-31`, usage
in
`apps/web/src/galleries/components/gallery-manager/gallery-manager.component.html:76-87`

- With `dragAndDrop=true`, the component styles itself as clickable (`cursor:
  pointer`, hover/focus states) and removes the focus outline (`outline: none`).
  But the consumer has to add `role="button"`, `tabindex="0"`, and the
  Enter/Space handlers. Any new consumer that forgets those gets a
  pointer-styled element keyboard users can't reach. Move `role`/`tabindex` into
  `host` bindings that depend on `dragAndDrop()`, and emit an `activated`
  output.
- `outline: none` + a border-color change from `outline-variant` to `primary` is
  a weak focus indicator (WCAG 2.4.7/2.4.11). Keep a visible `outline` on
  `:focus-visible`.
- Drag-and-drop doesn't exist on touch devices, and `:hover` "sticks" after a
  tap on iOS/Android. Wrap the hover styles in `@media (hover: hover)`. The
  "drop files here" copy should probably change on touch devices (consumer-side,
  but worth documenting).
- `padding: 48px 24px` (`dim-medium * 6 / * 3`) takes a large share of a phone
  viewport. Reduce it on narrow screens.
- The `aside` slot is always hidden (`.hidden { display: none }`). This is a
  non-obvious API ("anything projected into `aside` is invisible"). It's used
  for the file input. Document it, or replace it with a dedicated `hidden` slot
  name / a proper file-input integration.

### M10. `ui-card-item-list`: small touch targets, weak link affordance, stray scaffold file

`libs/ui/src/layouts/components/card-item-list/*`

- Rows are 14px text + 8px vertical padding (≈36px tall), and the first/last
  rows lose their outer padding. That's below the 44–48px touch target
  recommendation for links tapped on phones. Use `min-height: 48px` with flex
  alignment on `(pointer: coarse)`.
- Links have `text-decoration: none`, and only a `font-weight: 500` difference
  from the plain `span` rows. Colour/weight alone isn't enough to tell links
  apart (WCAG 1.4.1), and the hover underline is missing on touch.
- `card-item-list.component.html` (`<p>ui-card-item-list works!</p>`) is an
  orphaned generator file. The component uses an inline `template`. Delete it.
- `<ng-content select="a,span">` silently drops anything else (`button`, custom
  components). Consider a semantic `<ul role="list">` with an item directive,
  which would also announce "list, N items" to screen readers.

### M11. `ui-section-header` hard-codes `<h2>` and renders an empty description

`libs/ui/src/layouts/components/section-header/section-header.component.html:3,
10-12`

- A fixed `<h2>` can break the document outline when a section is nested or used
  under another `h2`. Accept a heading `level` input, or project the heading the
  way `ui-page-header` does.
- `.description` is always rendered. With no description you get an empty div
  plus a 4px flex gap. Wrap it in `@if`.

### M12. `ui-page-header` fixed row height and brittle content projection

`libs/ui/src/layouts/components/page-header/page-header.component.scss:4`,
`.html:3, 7, 21`

- `grid-template-rows: 40px max-content` clips or overlaps long titles that wrap
  on tablets / narrow desktop windows. Use `minmax(40px, auto)`.
- `<ng-content select="div">` takes **any** projected `div` as the sub-header,
  and `select="button,.action"` misses `<a matButton>` actions unless they also
  have `.action`. Use explicit attribute slots (`[uiPageHeaderSubtitle]`,
  `[uiPageHeaderActions]`). That makes the API self-documenting.
- On mobile, the actions row isn't allowed to wrap (`flex-direction: row` with
  no `flex-wrap`). Two or three text buttons plus Back overflow on a 360px
  screen. Add `flex-wrap: wrap`.

### M13. Status/feedback components aren't announced to assistive tech

- `ui-block-loader`, and the spinner branch of `ui-card-state`: add
  `role="status"` / `aria-live="polite"` on the host, and give the spinner an
  `aria-label` (in `card-state` there's no visible text at all).
- The error branch of `ui-card-state` and `ui-block-notice` with `isError`: use
  `role="alert"` (or `aria-live="assertive"`).

These components exist to report asynchronous state, so screen reader users
currently get no feedback when loading finishes or fails.

### M14. Tests are mostly smoke tests

- 12 of the 18 suites only assert `should create`.
- `WhenError` (H3), `DomainPipe` (M8) and `ScaleQuantityPipe` have no real tests
  at all. These are the units with actual logic.
- A single assertion on rendered text would have caught H1.

**Suggested minimum:** input → DOM tests for `card-state` (each branch),
`mini-badge` (CSS vars/class), `section-header` (icon/description
present/absent), `page-header` (back button emits), `menu-bar` (renders the
items passed in after M1); full branch coverage for the pipes and the directive.

## Recommended order of work

1. **Quick fixes (under an hour):** H1, H4, L1–L5, L13, delete the orphaned
   template (M10), and the `tsconfig.lib.json` exclude (H2).
2. **Correctness:** H3 (with tests), M8, M7 (i18n of the dialogs and pipes).
3. **Mobile/a11y pass:** M4, M5, M9, M10, M12, M13, L6, L9, then a manual check
   on a 360×800 portrait phone, a landscape phone, and with

   delete the stories) and grow the test suite (M14).

## What is done well

- Uses modern Angular throughout: standalone components, `OnPush` everywhere,
  signal inputs/outputs, `computed`, `@if`/`@for`/`@let`, `host` metadata,
  `inject()`.
- Material 3 system tokens (`--mat-sys-*`) are used consistently instead of
  hard-coded colours, so all 12 palettes and dark mode carry through.
- Tests run zoneless, with strict unknown-element/property checks.
- `strictTemplates`, `strictInputAccessModifiers` and strict TS are enabled.
- The pipes are pure and side-effect free. The `StripMarkdownPipe` and
  `TruncatePipe` specs are good examples to follow.
